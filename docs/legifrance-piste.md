# Légifrance / PISTE connector

# Connecteur Légifrance / PISTE

## Scope of this phase / Périmètre de cette phase

LODA collection only (`Fond.LODA_DATE`): Lois, Ordonnances, Décrets,
Arrêtés. JORF/KALI/JURI/CETAT/... are architecturally supported by the
same connector pattern but not implemented — extending `fond`/`natures`
to another collection means validating that collection's own filter
facets and consult route the same way this document did for LODA, not
assuming they're identical.

Collection LODA uniquement (`Fond.LODA_DATE`) : Lois, Ordonnances,
Décrets, Arrêtés. JORF/KALI/JURI/CETAT/... sont supportables
architecturalement par le même patron de connecteur, mais non
implémentés — étendre `fond`/`natures` à une autre collection implique
de valider les facettes de filtre et la route de consultation propres à
cette collection, exactement comme ce document l'a fait pour LODA, sans
supposer qu'elles sont identiques.

## Configuration

```json
{
  "environment": "sandbox",
  "keywords": ["cotisations", "contrat de travail"],
  "natures": ["DECRET", "ARRETE"],
  "max_items_per_run": 20,
  "lookback_days_first_run": 7
}
```

`natures` (optional) must be a subset of `LOI`, `ORDONNANCE`, `DECRET`,
`DECRET_LOI`, `ARRETE` (the confirmed `Nature2` enum, LODA subset).
`environment` defaults to `sandbox` — a watch never accidentally targets
production. `fond` is fixed to `LODA_DATE` in code for this phase (not a
config option) since only that collection's schema was verified.

`natures` (optionnel) doit être un sous-ensemble de `LOI`, `ORDONNANCE`,
`DECRET`, `DECRET_LOI`, `ARRETE` (l'enum `Nature2` confirmé, sous-ensemble
LODA). `environment` vaut `sandbox` par défaut — une veille ne cible
jamais accidentellement la production. `fond` est figé à `LODA_DATE`
dans le code pour cette phase (pas une option de configuration), car
seul le schéma de cette collection a été vérifié.

## What "full text" actually means here / Ce que « texte intégral » signifie réellement ici

`fetch()` does one `search` call per run, then one `consult/lawDecree`
call **per search result** (bounded by `max_items_per_run`) to get real
article text — not the two-phase "cheap search, then fetch only what
survives local relevance filtering" optimization the broader project
blueprint describes as a nice-to-have. This phase trades a small amount
of PISTE quota for a simpler, uniform `BaseConnector` contract shared with
the RSS connector (no connector-specific two-phase wiring in the
orchestrator). If `consult/lawDecree` fails for one result, that result
still becomes a candidate (title-only, `plain_text` falls back to the
title) rather than being dropped — the failure is recorded in
`source_metadata.consult_error` and logged, matching the PDF-extraction
fallback pattern already used by the manual-import wizard.

`fetch()` fait un appel `search` par exécution, puis un appel
`consult/lawDecree` **par résultat de recherche** (borné par
`max_items_per_run`) pour obtenir le vrai texte des articles — pas
l'optimisation en deux phases « recherche bon marché, puis récupération
uniquement de ce qui survit au filtrage de pertinence local » que le
blueprint plus large du projet décrit comme un « nice-to-have ». Cette
phase échange un peu de quota PISTE contre un contrat `BaseConnector`
plus simple et uniforme, partagé avec le connecteur RSS (pas de câblage
en deux phases spécifique au connecteur dans l'orchestrateur). Si
`consult/lawDecree` échoue pour un résultat, ce résultat devient quand
même un candidat (titre seul, `plain_text` retombe sur le titre) plutôt
que d'être abandonné — l'échec est enregistré dans
`source_metadata.consult_error` et journalisé, sur le même patron de
repli que celui déjà utilisé par l'assistant d'import manuel pour
l'extraction PDF.

## Known limitations / not implemented this phase / Limites connues / non implémenté à cette phase

- Only `LODA_DATE`. JORF/KALI/JURI/CETAT need their own verification pass.
  <br>Uniquement `LODA_DATE`. JORF/KALI/JURI/CETAT nécessitent leur
  propre passe de vérification.
- No pagination beyond one page per run (`pageNumber` fixed to `1`) —
  `max_items_per_run` bounds each run instead; incremental coverage comes
  from the `since`-date cursor across runs, same idea as the RSS
  connector's ETag cursor.
  <br>Pas de pagination au-delà d'une page par exécution (`pageNumber`
  figé à `1`) — `max_items_per_run` borne chaque exécution à la place ;
  la couverture incrémentale vient du curseur de date `since` d'une
  exécution à l'autre, même principe que le curseur ETag du connecteur
  RSS.
- `consult/ping` exists (confirmed) but isn't called anywhere yet. Neither
  is a live OAuth token request: **Test Connection** calls
  `validate_configuration()`, which by contract (shared with the RSS
  connector) never makes a network call — it only checks that
  `keywords`/`environment`/`natures` are well-formed and that credentials
  are *present* (env var or system parameter), not that PISTE actually
  *accepts* them. The only way to confirm credentials really work today is
  **Run Now**, which calls `fetch()` and therefore requests a real token.
  <br>`consult/ping` existe (confirmé) mais n'est appelé nulle part pour
  l'instant. Idem pour une vraie requête de token OAuth : **Tester la
  connexion** appelle `validate_configuration()`, qui par contrat
  (partagé avec le connecteur RSS) ne fait jamais d'appel réseau — elle
  vérifie seulement que `keywords`/`environment`/`natures` sont bien
  formés et que les identifiants sont *présents* (variable d'env ou
  paramètre système), pas que PISTE les *accepte* réellement. La seule
  façon de confirmer aujourd'hui que les identifiants fonctionnent
  vraiment est **Exécuter maintenant**, qui appelle `fetch()` et demande
  donc un vrai token.
- No rate/quota tracking beyond HTTP 429 retry-with-backoff — PISTE's
  actual quota policy (requests/day, etc.) was not found in either source
  and isn't enforced client-side.
  <br>Pas de suivi de quota/débit au-delà du retry-avec-backoff sur HTTP
  429 — la politique de quota réelle de PISTE (requêtes/jour, etc.) n'a
  été trouvée dans aucune des deux sources et n'est pas appliquée côté
  client.
